# dft-scan-atpg

Full-scan DFT insertion in Cadence Genus + stuck-at ATPG in Cadence Modus, on a
UART I wrote for the project instead of a benchmark netlist.

```
 RTL (rtl/top.v)
      │
      ▼
 Genus: synthesize ──► baseline area ──────────────┐
      │                                            │
      ▼                                            ▼
 Genus: muxed scan insertion ──► top_scan.v ──► area overhead %
      │
      ▼
 Modus: build_model / testmode / DRC / ATPG ──► stuck-at patterns
      │
      ▼
 Gate-level simulation of the vectors (zero mismatches = valid patterns)
```

**Status:** the RTL, constraints, Genus/Modus scripts and automation are done and
verified with open-source tools. All four chain counts (1/2/4/8) have been run
end-to-end on the lab server and their numbers are in the Results section below.
Still open: gate-level replay of the ATPG vectors. See **[docs/SERVER_HANDOFF.md](docs/SERVER_HANDOFF.md)** for exactly what
to run there, and **[docs/STEP_BY_STEP.md](docs/STEP_BY_STEP.md)** for the same
flow written as a beginner-level, command-by-command walkthrough with
troubleshooting.

## The design under test

`rtl/top.v` — 8N1 UART with a 4-entry TX FIFO and a 4-entry RX FIFO.

| Signal | Dir | Meaning |
|---|---|---|
| `clk` | in | single clock, everything is posedge |
| `rst_n` | in | asynchronous active-low reset |
| `wr_en`, `wr_data[7:0]` | in | push a byte into the TX FIFO |
| `tx_full`, `tx_empty` | out | TX FIFO status |
| `rd_en` | in | pop a byte from the RX FIFO |
| `rd_data[7:0]` | out | RX FIFO head |
| `rx_empty`, `rx_full` | out | RX FIFO status |
| `rx_err` | out | framing error on the frame that just ended |
| `baud_div[11:0]` | in | clk cycles per bit |
| `tx`, `rx` | out/in | serial line |

```
                 ┌─────────────────────── top ─────────────────────────┐
  wr_en/wr_data ►│ TX FIFO (4×8) ─► TX shifter + FSM ─┐                │
                 │      ▲                 ▲            ├──► tx ────────┼──►
                 │      └── pop           │ baud       │                │
                 │                       bit/bcnt     │                │
  rx ◄───────────┼── 2-FF sync ─► RX FSM + shifter ─► RX FIFO (4×8) ────┼──► rd_data
                 └─────────────────────────────────────────────────────┘
```

**Size:** ~129 flops (Yosys, before mapping — `make flops`). 15 ports. Small
enough that ATPG takes seconds, big enough that the numbers mean something.

### Why this design is easy to scan (on purpose)

The guide's most common failure mode is a clock or reset that Genus cannot
control in test mode. This DUT avoids the whole class of problems:

- one clock, one asynchronous reset, **both top-level ports** — no test-mode
  override mux, no internally generated clock;
- no latches, no clock gating, no tristate;
- FIFO storage is a plain register array, so it maps to flops (and therefore to
  scan flops) with any standard-cell library. If your library happens to infer a
  RAM macro for it, that macro is *not* scanned and coverage will tank — see
  Troubleshooting;
- every FSM state is reachable from reset, so ATPG is not fighting unreachable
  states.

## Results

Generated by `make results` into `results_table.md` (and `.csv`) from
`p2_scan/runs/*/kpi.txt` and `p2_atpg/runs/*/atpg_kpi.txt`. All four rows are
measured on the lab server (Genus 21.14-s082_1, Modus 22.10-p008_1):

| Chains (requested) | Chains built | Scan flops | Longest chain | Patterns | Approx. test cycles | Coverage | Area overhead | ATPG runtime (s) |
|---|---|---|---|---|---|---|---|---|
| 1 | 1 | 129 | 129 | 91 | 11830 | 100.00% | 17.2% | 1.5 |
| 2 | 2 | 129 | 65 | 92 | 6072 | 100.00% | 17.2% | 2.3 |
| 4 | 4 | 129 | 33 | 93 | 3162 | 100.00% | 17.2% | 4.7 |
| 8 | 8 | 129 | 17 | 94 | 1692 | 100.00% | 17.2% | 1.3 |

- Sweeping 1 → 8 chains cut approximate test cycles from 11830 to 1692
  (**7.0×**) with **no coverage change**: 100.00 % at every chain count. Scratch
  pieces of the story: pattern count drifts up 91 → 94 because chain order
  changes which faults can share a pattern, and the fault universe grows 4556 →
  4584 as the scan muxes add gates.
- Number of flip-flops: 129 before, 129 after — every flop is scannable at 1
  chain, so the chain is just all of them in a row. Chain lengths are uneven at
  the top end (8 chains = 17 + 7×16) since 129 does not divide by 8.
- 91 committed tests = 90 logic + 1 scan test; in full scan a test is one scan
  load, so patterns = tests.
- Coverage comes from `tbdata/modus_metrics`, the committed-test fault
  accounting. At 1 chain: **4556 tested of 4556 complete stuck-at faults, 0
  untested, 0 ignored**; at 8 chains: 4584 of 4584, 0 untested. Modus's
  interactive progress table printed 99.99 % for the same runs, which is a
  display artifact — quote the fault counts, not the spinner. (`write_vectors`
  also reported 262 cycles for 2 tester loops; that is the Verilog sample dump,
  not the pattern count.)

- Area overhead % = `(dft_area − baseline_area) / baseline_area × 100`
- Approx. test cycles = `patterns × (longest chain + 1)`
- Takeaway to write up: more chains cut test time nearly linearly but cost scan
  I/O pins — pins are the real constraint, which motivates compression
  (Project 4).

## Moving to the SSH server

Full detail in [docs/SERVER_HANDOFF.md](docs/SERVER_HANDOFF.md). The short
version:

```bash
git clone <this repo> ~/dft_projects/dft-scan-atpg
cd ~/dft_projects/dft-scan-atpg
# point the flow at the real cell library
ln -sf /pdk/path/cells.lib lib/cells.lib
ln -sf /pdk/path/cells.v   lib/cells.v
# sanity check that the kit has scan flops
grep -c -i sdf lib/cells.lib          # must be > 0

make sim lint                          # still green on the server
make baseline                          # -> p2_scan/runs/baseline/
make dft CHAINS=1                      # -> p2_scan/runs/c1/top_scan.v + reports
# check dft_rules_pre/post + scan_chains.rpt, fix top.pinassign pin names
make atpg CHAINS=1                     # -> p2_atpg/runs/c1/
bash scripts/sweep_chains.sh 1 2 4 8   # full experiment
make results                           # -> results_table.md
```

## Troubleshooting

| Symptom | Cause / fix |
|---|---|
| Genus: `Cannot find library cells.lib` | `lib/cells.lib` missing; see `lib/README.md` |
| `connect_scan_chains` inserts nothing | library has no scan flops, or `dft_scan_style` not set before `syn_map` |
| DFT rule violations on clock/reset | a clock/reset is generated internally (not this DUT — your later design) |
| Modus `build_testmode` fails | pin names in `top.pinassign` don't match the netlist; copy from `scan_chains.rpt` |
| `verify_test_structures` chain-shift error | `SE` or `rst_n` not held constant during shift; check the pinassign |
| Coverage < 90% | usually a DRC/controllability issue, or an unscanned macro (FIFO array inferred as RAM) |
| Gate-level sim mismatches at t=0 | flops without reset in the FIFO arrays are X; Modus vectors may need an init sequence |
